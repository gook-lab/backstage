버튼 색 실험을 이틀 돌렸더니 B가 전환율 12% 높게 나왔어요. 그런데 대시보드를 새로고침할 때마다 숫자가 조금씩 바뀌어요. 어제는 유의하던 결과가 오늘은 아니에요.

이 글은 실험 결과가 흔들리는 이유를 서버 쪽 기록과 계산에서 찾아봐요. 배정과 노출을 나눠 기록하는 법, 분석 단위를 맞추는 법, 결과를 자주 들여다볼 때 생기는 문제, 여러 지표를 볼 때의 함정을 다뤄요. 아래 시뮬레이터에서 판정 방식과 기록 방식을 바꿔 보면 같은 실험도 결과가 어떻게 달라지는지 확인할 수 있어요.

이 글은 실험 토글을 배정하는 방법은 다루지 않아요. 배정과 롤아웃은 [기능 플래그와 점진 배포](/m/feature-flags)에서, 실험 중 오류를 보는 방법은 [관측성](/m/observability)에서, 집계 응답을 만드는 방법은 [대시보드 집계](/m/dashboard-aggregation)에서 다뤄요.

## 증상 — 결과가 매번 바뀌는 대시보드

FE에서는 같은 실험의 전환율이 조금씩 흔들려 보여요. 원인을 모르면 "서버 집계가 틀렸다"고 의심하기 쉬워요. 집계 코드가 틀리지 않았는데도 숫자가 흔들리는 경우가 많아요. 문제는 무엇을 로그에 남겼는지와 언제 결과를 봤는지에 있어요.

세 가지가 함께 얽혀 있어요. 실험에 들어간 사람과 화면을 본 사람이 다를 수 있어요. 세는 단위가 배정 단위와 다를 수 있어요. 결과를 본 시점이 미리 정한 시점이 아닐 수 있어요. 이 중 하나만 어긋나도 숫자는 믿기 어려워져요.

## 배정과 노출 — 실험에 들어간 사람과 본 사람 나누기

배정(assignment)은 사용자를 A나 B에 넣는 일이에요. 노출(exposure)은 사용자가 실제로 B 화면을 본 일이에요. 둘은 같지 않아요. 버튼이 있는 페이지까지 가지 않은 사용자는 B에 배정되었어도 버튼 색을 보지 못해요.

실험 결과를 믿으려면 배정이 사용자마다 고정되어 있어야 해요. 노출까지 같이 기록해야 "실제로 본 사람끼리 비교했는지"를 확인할 수 있어요.

배정 시점에만 기록하면 본 적 없는 사람이 분석에 섞여요. 예를 들어 하루 방문자 1,000명 중 버튼 페이지까지 간 사람이 절반이라면(예시), 배정 기록으로 세면 B 효과가 절반 수준으로 희석돼요. 노출 시점에만 기록하면 정확한 효과에 가까워지지만, 표본은 줄어들어요.

| 기록 방식    | 분석 대상               | 장점                                   | 단점                                     |
| ------------ | ----------------------- | -------------------------------------- | ---------------------------------------- |
| 배정 시 기록 | 배정된 모든 사용자      | 표본이 크고, 배정 순서가 그대로 남아요 | 버튼을 못 본 사람이 섞여서 효과가 줄어요 |
| 노출 시 기록 | 실제로 화면을 본 사용자 | 설정한 효과가 그대로 드러나요          | 표본이 줄고, 노출 기록이 빠지면 편향돼요 |

배정 기록을 기준으로 결과를 보면 이 효과 희석을 "보수적인 추정"으로 받아들일 수 있어요. 다만 노출 기록을 남기지 않은 채 결과를 "효과가 있었다"로 바꿔 해석하면 안 돼요.

## 노출 기록 시점 — 화면이 그린 뒤 보내기

노출 이벤트는 FE가 보내요. 언제 보내야 하는지가 정확도를 정해요. 배정 응답을 받은 순간 보내면 아직 화면에 그려지지 않은 사용자를 세게 돼요. 네트워크가 늦어서 화면이 B를 그리지 못한 경우도 생겨요.

FE는 보통 이렇게 다뤄요.

- 버튼 컴포넌트가 실제로 화면에 나타난 뒤 노출 이벤트를 보내요.
- 배정 값은 응답에 함께 받고, 노출 이벤트에는 같은 배정 값과 실험 id를 실어요.
- 같은 화면을 다시 그릴 때마다 보내지 않도록, 페이지 안에서 한 번만 보내요.

노출 기록을 플래그 평가 호출과 같은 자리에 두면 누락을 줄일 수 있어요. 다만 평가 호출이 화면에 그려지지 않는 곳에서도 일어난다면, 그 호출을 노출로 세면 안 돼요.

## 분석 단위 — 배정 단위와 세는 단위 맞추기

실험은 보통 사용자 단위로 배정해요. 그러면 분석도 사용자 단위여야 해요. 세션이나 페이지뷰로 세면 같은 사람이 여러 번 세여서 표본이 부풀어요. 같은 사람이 같은 쪽에서 여러 번 전환하면, 독립적인 관측이 많아 보여서 유의하다고 나오기 쉬워요.

| 세는 단위 | 맞는 경우                         | 생기는 착시                              |
| --------- | --------------------------------- | ---------------------------------------- |
| 사용자    | 사용자 단위로 배정했을 때         | 없어요. 배정과 분석이 같은 대상이에요    |
| 세션      | 세션마다 독립적으로 배정했을 때만 | 같은 사용자의 세션이 독립처럼 세여요     |
| 페이지뷰  | 페이지뷰마다 배정하는 설계일 때만 | 한 사람이 여러 번 세여서 표본이 부풀어요 |

배정 단위와 분석 단위가 다르면 먼저 설계를 다시 보는 편이 좋아요. 결과를 고쳐 읽기보다 원본 설계가 어긋나 있다는 것을 기록해 두는 편이 나아요.

## 표본 비율 점검 — SRM을 결과보다 먼저 보기

설계에서 A와 B를 절반씩 배정했다면, 실제 집계도 대략 절반이어야 해요. 이 기대 비율과 실제 비율이 다르면 샘플 비율 불일치(SRM, sample ratio mismatch)를 의심해요.

KDD 2019 논문 페이지는 SRM을 관찰된 비율이 기대와 다른 상황으로 정의해요. 그 논문은 SRM을 여러 데이터 품질 문제의 신호로 보고, 원인을 모른 채 무시하면 나쁜 변경이 좋아 보이거나 좋은 변경이 버려질 수 있다고 설명해요. 탐지는 간단한 통계 검사로 하고, 원인을 찾는 일이 더 어렵다고 말해요.

Wikipedia는 SRM을 카이제곱 검정으로 찾는다고 설명해요. 임계값은 팀이 정해요. 이 글에서는 특정 임계값을 권하지 않아요.

SRM이 나오면 결과를 보기 전에 배정 기록부터 확인해요. 흔한 원인은 배정 응답과 노출 기록이 다른 경로로 저장되는 경우, 봇이 한쪽에만 몰리는 경우, 캐시가 같은 배정을 반복해서 돌려주는 경우예요(예시). 원인을 고치지 않고 결과를 읽으면, 그 결과는 설계된 실험의 결과가 아니에요.

## 중간 들여다보기 — 매일 보고 멈출 때의 거짓 양성

결과를 자주 보는 습관은 가장 흔한 문제예요. "유의하면 멈춘다"는 규칙을 쓰면 효과가 없어도 잘못 멈출 확률이 올라가요.

Evan Miller는 표본 크기를 미리 정하지 않고 유의해지면 멈추는 방식이 반복 유의성 검정의 오류를 만든다고 설명해요. 그의 예에서는 기준 전환율 50%인 로고 변경이 효과가 없어도, 유의 수준 5%에서 멈추는 규칙으로 실험하면 잘못 유의하다고 나온 비율이 26.1%였어요. 열 번 들여다보면 보고된 1% 유의성이 실제로는 5%에 가깝다고도 말해요.

Statsig 문서도 고정 기간 검정(t 검정, z 검정)은 기간 끝에 한 번 보는 것을 전제로 하고, 지속적으로 들여다보면 거짓 양성이 선택한 유의 수준 이상으로 올라간다고 설명해요. GrowthBook 문서도 같은 문제를 들여다보기 문제(peeking)라고 부르고, 들여다보면 거짓 양성이 명목 5%보다 크게 부풀어 오른다고 설명해요.

해결은 두 갈래예요.

| 방식                           | 하는 일                                           | 주의할 점                              |
| ------------------------------ | ------------------------------------------------- | -------------------------------------- |
| 고정 기간 판정                 | 기간과 표본을 미리 정하고 끝에 한 번만 봐요       | 중간에 멈추면 결과가 무효가 돼요       |
| 순차 검정 (sequential testing) | 중간 확인 시점을 정하고 그에 맞게 기준을 보정해요 | 보정 방식을 제품이 제공하는지 확인해요 |

Statsig 문서는 중간 분석 창마다 p값과 신뢰구간을 보정한다고 설명해요. 같은 문서는 들여다보기를 일반적으로 권하지 않는다고도 말해요. 그러니 "보려면 보정된 방식을 쓰고, 아니면 끝날 때까지 보지 않는다"로 정리하는 편이 안전해요.

## 유의성과 신뢰구간 — 차이를 표준오차로 나누기

두 집단의 전환율 차이가 우연으로 설명되는지 보려면 차이를 그 불확실성으로 나눠요. 그 값을 z 값이라고 불러요.

NIST 가설 검정 페이지는 정규 근사를 쓴 z 검정에서 통계량이 임계값 z(1-α/2)보다 절대값으로 크면 귀무가설을 기각한다고 설명해요. 이 글의 시뮬레이터는 양측 5% 수준에서 z 값의 절대값이 약 1.96 이상이면 유의하다고 판정해요. 이 숫자는 표준정규분포의 97.5% 분위수에서 가져왔어요.

NIST 페이지는 정규 근사가 유효하려면 표본이 충분해야 한다는 조건도 밝혀요. 표본이 작으면 z 값을 그대로 믿기 어려워요.

시뮬레이터는 신뢰구간을 따로 계산하지 않고 z 값과 임계값을 비교해서만 판정해요. 신뢰구간의 정의와 공식은 이 글에서 확인한 출처에서 다루지 않아서 본문에 쓰지 않았어요.

유의한 결과에도 함정이 있어요. 표본이 작을 때 유의하다고 나온 실험은 실제 효과보다 크게 측정되기 쉬워요. 시뮬레이터의 "유의하다고 나온 실험의 평균 효과"에서 이 차이를 볼 수 있어요.

## 여러 지표와 여러 변형 — 다중 비교의 함정

지표를 열 개 보고, 변형을 세 개 비교하면 어딘가에서 우연히 유의한 결과가 나와요. 지표가 많을수록 "하나는 유의하다"는 결과가 쉽게 나와요. 그래서 결과 대시보드에 지표를 늘어놓을수록 판단은 약해져요.

대응은 세 가지로 정리해요.

- 주요 지표 하나를 미리 정해요. 그 지표만 판정에 써요.
- 가드레일 지표(결제 실패, 오류율, 응답 시간)는 방향만 확인하고, 유의성 판정에서 분리해요.
- 나머지 지표는 탐색용으로 보고, 다음 실험의 가설로 넘겨요.

## 이벤트 중복과 지연 도착 — 멱등 이벤트 id로 세기

노출 이벤트는 네트워크 재시도로 중복될 수 있어요. 반대로 앱이 닫히면서 일부가 유실될 수도 있어요. 중복을 그대로 세면 한 사람이 여러 번 세여서 분석 단위가 깨져요.

각 노출 이벤트에 멱등 이벤트 id를 붙이면 서버가 같은 이벤트를 한 번만 세요. 이 id는 같은 노출을 다시 보낼 때 같은 값이어야 해요. 매번 새로 만들면 중복을 걸러낼 수 없어요.

지연 도착 이벤트는 기록 시각과 도착 시각이 달라요. 집계 기간을 정할 때 "기록 시각 기준"인지 "도착 시각 기준"인지 정하고, 늦게 온 이벤트를 어느 기간에 넣을지 같이 정해야 해요. 기록 시각 기준으로 넣으면 과거 결과가 나중에 바뀔 수 있어요. 이 문제는 [대시보드 집계](/m/dashboard-aggregation)의 재계산 구간과 같은 생각으로 다뤄요.

## FE 체크 포인트

**배정 값과 노출 이벤트를 함께 보내요.** 노출 이벤트에 배정 값과 실험 id가 없으면 서버가 어느 쪽 화면을 봤는지 알 수 없어요.

**노출 이벤트는 화면이 그린 뒤 한 번만 보내요.** 배정 응답을 받은 순간 보내면 실제로 보지 않은 사용자가 섞여요.

**이벤트에 멱등 id를 붙여요.** 재시도와 중복 전송이 생겨도 같은 노출은 한 번만 세져요.

**결과를 볼 시점을 실험 시작 전에 정해요.** 매일 보는 습관이 있다면 판정 방식을 고정 기간으로 바꾸거나, 보정된 순차 검정을 쓰는 것을 BE와 같이 정해요.

## 시뮬레이터 안내

아래 시뮬레이터는 기준 전환율 10%, 기간 14일로 가정한 가짜 방문자를 만들어요. 실험을 300번 같은 조건으로 돌려서 평균을 보여 줘요. 모든 수치는 예시예요.

1. 판정 방식을 `기간 끝에 한 번`으로 두고, 효과 없을 때 잘못 찾아낸 실험의 비율을 확인해요.
2. `매일 보고 유의하면 멈춤`으로 바꾸면 같은 조건에서 잘못 찾아내는 비율이 늘어나요.
3. 노출 기록 방식을 `배정 시 기록`으로 바꾸면 측정된 평균 효과가 실제 효과보다 작아져요.
4. 버튼 도달 비율을 낮추면 배정 기록의 희석이 커져요.
5. 실제 효과를 0으로 두고 `유의하다고 나온 실험의 평균 효과`를 보면, 효과가 없는데도 유의하게 나온 실험에서 측정 효과가 얼마나 나오는지 볼 수 있어요.

차트는 첫 번째 실험의 날짜별 z 값이에요. 매일 보고 멈추는 방식에서는 선이 기준선을 넘는 순간 멈춰요.

## 정리 — 배정 · 노출 기록 · 분석 단위 · 판정 시점 결정

실험 결과는 배정과 노출을 따로 기록하고, 분석 단위를 배정 단위와 맞춘 뒤, 미리 정한 기간에 한 번 판정할 때 믿을 수 있어요. 노출 기록은 화면이 그린 뒤 보내고, 이벤트에는 멱등 id를 붙여요. 결과를 먼저 보기 전에 SRM을 확인하고, 여러 지표는 주요 지표 하나로 판정해요. 매일 보는 습관이 필요하면 보정된 순차 검정을 쓰거나 판정 규칙을 실험 시작 전에 고정해요.
